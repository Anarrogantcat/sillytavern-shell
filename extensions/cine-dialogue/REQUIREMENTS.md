## 二、设计铁律（冻结，不许改）

1. **五层**：`台词 / 动作 / 感官 / 心理 / 旁白`
2. **颜色 = 角色** · **样式 = 层**（一行里层样式统一，颜色跟着角色走）
3. **标签绝不出现在界面上**（`名字·层` 只用于解析，不进 UI）
4. **台词 / 动作 / 感官 / 心理 = 第一人称「我」**；**旁白 = `旁白·内容`（没有名字）**
5. 用户角色（`{{user}}`）单独绑色：**男 ⇒ 蓝 / 女·扶她 ⇒ 紫**；**其他角色不套用**（各自按出场顺序自动配色）

## 六、状态栏 / 选项栏不见了怎么排（2026-10-14 用户实测：是预设问题）

**现象**：卡的**状态栏**（日期 / 地点 / 用户列表）或**选项栏**（那排可点的选项）不见了。
**用户实测结论**：**是预设的问题**，不是插件 ✓（换回去就"又有了"）。

**机制**：状态栏 / 选项栏是**卡自带的前端条目**画出来的 ——
卡的消息里有占位符（`<StatusPlaceHolderImpl/>` / `<option/>` / `<StatusBar>`），
由**卡自己的正则 / TavernHelper 脚本**把它替换成界面；而这些脚本挂在**该卡配套的预设**上。
⇒ 若在**别的预设**下生成 / 使用我们的专属预设，卡的条目没被带过来 ⇒ 占位符没人接手 ⇒ 界面消失。

**排查顺序（先别怀疑插件）**：
1. 切回**这张卡配套的预设** ⇒ 状态栏回来没有？回来了 ⇒ 就是预设带漏了 ✓
2. 生成我们的专属预设时，**必须先切到这张卡配套的预设**（面板里「当前预设」会显示底稿名 ✓）
3. 插件侧已实测**不会**破坏占位符（见下），所以插件不是嫌疑对象 ✓

**插件侧的证据（可复跑）**：库里 168 楼含前端占位符，我们接手 26 楼，
接手后占位符**原样保留、不被转义、不被嵌套**（在 `.cd-root` 之外的顶层）⇒ **0 丢失** ✓

**预览定稿的规则（照抄，不许再"重新猜"）**：
```css
/* * 一条消息 = 一个网格
   * 名字列宽 = 整条消息最长的名字（不是每段各算各的）
   * 段落之间的内容也对齐
   * row-gap 是行与行之间唯一有效的间距手段（.row 是 display:contents，margin 对它无效） */
.grid{ display:grid; grid-template-columns:max-content 1fr; row-gap:.8em }
.row{ display:contents; color:var(--c, inherit) }
/* 名字列：靠右紧贴内容，后面留一个间隔 */
.who{ font-weight:600; opacity:.85; text-align:right; padding-right:.6em; white-space:nowrap }
/* 段与段之间的分隔线，横跨两列 */
.grpsep{ grid-column:1 / -1; height:0; border-top:1px solid var(--line); margin:1.25em 0 }
/* 空行分段 */  if(gi > 0) html += '<div class="grpsep"></div>';
```
**其它定稿口径**：标签一律不显示 ✓ · 格式错的行显式标红 ✓ · 旁白无名字且对齐正文列 ✓ ·
角色 → 色、层 → 样式（人称/层名不写死）✓
