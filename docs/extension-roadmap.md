# 扩展完善与更新方向（card-compat / plot-pilot）

> 基于本会话实测出来的问题清单排的优先级。P1 = 直接影响正确性/体验，P2 = 能力扩展，P3 = 打磨。
>
> **版本说明（2026-09-25 补）**：本文写于 card-compat **0.2.7** / plot-pilot **0.1.2** / 壳 **2.0.3**。
> 当前实际版本：card-compat **0.16.0**、plot-pilot **0.2.2**、壳 **2.2.24** —— 所以下面 P1/P2/P3 里有几条**已经做完**，
> 各条已按「✅ 已落地（版本）」或「⌛ 仍待做」标注；能力基线以 `extensions/<名字>/README.md` 与 `CHANGELOG.md` 为准。

## 一、card-compat（现 0.16.0）

### 已完成的能力（作为基线）
锚点守护 / 数据块守护 / 字号 / 结尾提醒注入（含必更字段与格式示例）/ 历史楼层规范化 / 覆盖度核对 / 引号与 YAML 修复 / 严格 YAML 校验（自带 js-yaml）/ 未声明块清理 / 变量块兜底（静默补丁 + 写回 MVU）

### P1（先做）
1. ⌛ **兜底链路的最后一公里**：变量块兜底目前依赖 `window.Mvu` 可见；若写回失败，自动改为调用 MVU 的「重新处理变量」入口（或直接调用 MVU 的额外解析 API），并在面板给出明确指引。
2. ✅ **已落地（0.9.4 / 0.11.0）**：补丁生效自检 + 状态级核对表 +「本轮补丁」结果行（原「本卡声明 vs 消息实际」对照表）—— 面板一眼看清「写了但变量没变」的楼层，不必翻日志。**仍缺**：把「未声明块」也列进同一张表（现在只在日志里）。
3. ⌛ **失败可见化**：`data-missing`、`varfix-invalid`、`block-yaml-issue` 这类硬失败在连续 N 轮后弹一次 toast（现在只有面板日志，用户看不到）。
4. ✅ **已落地（0.6.0 起，0.13.0 扩到 schema）**：`profileOf()` / schema / 作用域均带缓存，`invalidateProfile()` 在 `CHAT_CHANGED`、换卡时失效（大卡世界书 60KB+ 不再每层重扫）。

### P2（能力）
5. ✅ **已落地（0.4.0 起）**：`validatePatchPaths()` + 面板「声明命中 / 组内未声明 / 越界」—— 卡的「变量更新规则」被解析成允许路径集合，越界补丁只提示不改写。
6. ✅ **已落地**：覆盖度趋势方块条（最近 10 轮对比前 10 轮，`trend()` 可读）—— 方便判断「换模型 / 换预设」的效果。
7. ⌛ **多结构块支持**：目前 `stripUndeclaredBlocks` / YAML 修复以「卡声明的标签族」为单位；计划补齐"同一卡多套状态栏模板"的场景（例如开局面板与状态栏并存）。
8. ✅ **已落地**：面板已拆成「守护 / 清理 / 校验 / 兜底 / 日志」+ 兼容性体检分区，减少误操作。

### P3（打磨）
9. ⌛ 与 MVU 的「额外模型解析」打通：插件兜底失败时自动触发 MVU 的额外解析（一次点击的替代）。
10. ✅ **已落地（0.5.0 起）**：面板中英双语（`lang: auto|zh|en`）。

## 二、plot-pilot（现 0.2.2）

### 已完成的能力（作为基线）
按卡探测剧本/蓝图信号 / 两个按钮（文案可改）/ 每卡覆盖 / api+dom 双发送通道 / 旧脚本冲突待命 / 「任何卡都显示推进节点」开关 / 发送给模型的内容可配

### P1
1. **推进目标可指定**：「推进节点」支持填写目标（如「推进到 PG.5」「下一个 step」「下一章」），文案里插 `{step}`；面板记住上次用的目标。
2. **识别卡自己的选项**：当该层消息里有 `<options>`/行动选项时，按钮可展开成"点第 N 项"（把选项号直接发出去），比通用"推进"精确得多。
3. **快捷键**：`Alt+Enter` 续写、`Alt+Shift+Enter` 推进；面板可改。

### P2
4. **自动续写 N 轮**：可设条件（例如「结尾没有 `<options>` 就再推一轮」「连续 N 轮无用户输入」），带急停开关与轮数上限。
5. **与 card-compat 联动**：推进前若发现上一层缺变量块，先补块再推进（避免状态栏停在旧值上推进剧情）。

### P3
6. 按钮文案 EN；7. 按钮位置（发送栏上方 / 输入框右侧）可选。

## 三、版本节奏与流程

- 版本号规则（2026-09-25 校准为现行规则）：patch **无上限**（唯一例外：minor 为 36 时最多到 6，封顶点 `X.36.6`）、minor ≤ 36；加功能 → minor +1 且 patch 归零，修 bug → patch +1。当前壳 `2.2.24`
- 扩展自身版本独立递增（card-compat **0.16.0** / plot-pilot **0.2.2**）；**扩展更新不需要发套壳**，推 `main` + 重建 `index.json` 即可
- 每次改动：升版本 → 重建 index → 跑全部夹具（compat / plot-pilot / ext-remote / ext-deploy / cf / toolbox）→ 提交推送 → 需要时打 tag 发版
- **2026-09-25 审计整改落点**：壳 2.2.14~2.2.19 修了渲染层 XSS / 回滚包路径穿越 / 假备份 / dataRoot 校验 / 发布链闸门 / NSIS 静默与归属标记；card-compat 0.14.0~0.15.0 修了模板组上限（防卡死）+ 解析/写入/作用域/校验共 12 处 bug + 长聊内存；plot-pilot 0.2.0~0.2.1 修了重复发送与谎报「已发送」。审计清单的 P1 已全部闭环。逐条见各 CHANGELOG 与 `scripts/compat-logic-test.mjs` 的「夹具 43」
