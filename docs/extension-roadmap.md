# 扩展完善与更新方向（card-compat / plot-pilot）

> 基于本会话实测出来的问题清单排的优先级。P1 = 直接影响正确性/体验，P2 = 能力扩展，P3 = 打磨。

## 一、card-compat（现 0.2.7）

### 已完成的能力（作为基线）
锚点守护 / 数据块守护 / 字号 / 结尾提醒注入（含必更字段与格式示例）/ 历史楼层规范化 / 覆盖度核对 / 引号与 YAML 修复 / 严格 YAML 校验（自带 js-yaml）/ 未声明块清理 / 变量块兜底（静默补丁 + 写回 MVU）

### P1（先做）
1. **兜底链路的最后一公里**：变量块兜底目前依赖 `window.Mvu` 可见；若写回失败，自动改为调用 MVU 的「重新处理变量」入口（或直接调用 MVU 的额外解析 API），并在面板给出明确指引。
2. **"本卡声明 vs 消息实际"对照表**：面板里列出「本卡要求的标签 / 本轮缺的标签 / 本轮多出来的未声明块」，一眼看清问题，不必翻日志。
3. **失败可见化**：`data-missing`、`varfix-invalid`、`block-yaml-issue` 这类硬失败在连续 N 轮后弹一次 toast（现在只有面板日志，用户看不到）。
4. **性能**：`profileOf()` 每次都全量扫卡的文本；大卡（世界书 60KB+）在每层守护时重复构建 → 缓存 profile，`CHAT_CHANGED` / 换卡时失效。

### P2（能力）
5. **变量路径白名单**：把卡的「变量更新规则」解析成允许的路径集合，对模型/兜底补出的 JSONPatch 做**路径校验**，拒绝写卡里不存在的字段（现在只校验 JSON 结构与 op/path 是否存在）。
6. **补丁覆盖率历史**：记录最近 N 层覆盖度，面板画一条小趋势，方便判断"换模型/换预设"的效果。
7. **多结构块支持**：目前 `stripUndeclaredBlocks` / YAML 修复以「卡声明的标签族」为单位；计划补齐"同一卡多套状态栏模板"的场景（例如开局面板与状态栏并存）。
8. **面板分组**：把现在的长列表拆成「守护 / 清理 / 校验 / 兜底 / 日志」五组，减少误操作。

### P3（打磨）
9. 与 MVU 的「额外模型解析」打通：插件兜底失败时自动触发 MVU 的额外解析（一次点击的替代）。
10. 面板 EN 文案（套壳已有 i18n，ST 扩展面板目前只有中文）。

## 二、plot-pilot（现 0.1.2）

### 已完成的能力（作为基线）
按卡探测剧本/蓝图信号 / 两个按钮（文案可改）/ 每卡覆盖 / api+dom 双发送通道 / 旧脚本冲突待命 / 「任何卡都显示推进节点」开关 / 发送给模型的内容可配

### P1
1. **推进目标可指定**：「推进节点」支持填写目标（如「推进到 PG.5」「下一个 step」「下一章」），文案里插 `{step}`；面板记住上次用的目标。
2. **识别卡自己的选项**：当该层消息里有 `<options>`/行动选项时，按钮可展开成"点第 N 项"（把选项号直接发出去），比通用"推进"精确得多。
3. **快捷键**：`Alt+Enter` 续写、`Alt+Shift+Enter` 推进；面板可改。

### P2
4. **自动续写 N 轮**：可设条件（例如「结尾没有 `<options>` 就再推一轮」「连续 N 轮无用户输入」），带急停开关与轮数上限。
5. **与 card-compat 联动**：推进前若发现上一层缺变量块，先补块再推进（避免状态栏停在旧值上推进剧情）。

### P3
6. 按钮文案 EN；7. 按钮位置（发送栏上方 / 输入框右侧）可选。

## 三、版本节奏与流程

- 版本号规则：patch ≤ 6、minor ≤ 36；当前 `2.0.3` → 后续 `2.0.4 … 2.0.6` → `2.1.0`
- 扩展自身版本独立递增（card-compat 0.2.7 / plot-pilot 0.1.2）；**扩展更新不需要发套壳**，推 `main` + 重建 `index.json` 即可
- 每次改动：升版本 → 重建 index → 跑全部夹具（compat / plot-pilot / ext-remote / ext-deploy / toolbox）→ 提交推送 → 需要时打 tag 发版
